1. INTRODUCTION                                          *lvim-tex-introduction*

lvim-tex owns what is TeX-SPECIFIC and nothing else. texlab and latexindent are
wired by lvim-lang, the grammars belong to lvim-ts, the snippet engine to
lvim-snippets. What no generic layer can express is the document itself: which
file IS the document, how it is built, what its log means, and where a position
in the PDF maps back to in the source.

This release covers phases 1-4 — the project model, builds (one-shot and a
save-driven loop), the log → diagnostics pipeline, the build panel, the viewer
layer with the PDF page as its default viewer, and SyncTeX in both directions
with the external viewers. The TOC panel, the editing operators, conceal and
the maths abbreviations follow in later phases. Nothing is documented here that
is not implemented.

2. REQUIREMENTS                                          *lvim-tex-requirements*

    - Neovim 0.11+

    - lvim-utils
    - the `latex` and `bibtex` treesitter grammars (for the include graph)
    - optional: lvim-lang, whose latex provider owns the LSP wiring

3. SETUP                                                        *lvim-tex-setup*

Install with lvim-installer, or with Neovim's native |vim.pack|: >lua
    vim.pack.add({ "https://github.com/lvim-tech/lvim-tex" })

    require("lvim-tex").setup({})
<
`setup()` merges your options into the live configuration in place, so every
reader of `require("lvim-tex.config")` sees the effective values.

4. THE PROJECT MODEL                                          *lvim-tex-project*

A LaTeX project is compiled through ONE root document. Building the chapter you
happen to be editing would produce a document with no preamble, so every action
resolves the root first, through a chain of decreasing evidence strength:

    1. a `% !TEX root = …` magic comment, followed transitively (max 5 hops)
    2. `\documentclass[main.tex]{subfiles}` — the subfiles package names its
       main file in the optional argument
    3. a marker file upward: `.texlabroot`, `texlabroot`, `.latexmkrc` — the
       same markers texlab roots on, so the LSP and the builder always agree
    4. an upward `\documentclass` scan: this file, its directory, then ancestors
    5. the file itself

Step 2 must precede step 4 because a subfile carries a `\documentclass` of its
own. Set `root.subfiles = "subfile"` to compile the subfile you are in instead.

                                                       *lvim-tex-target-toggle*
The COMPILE TARGET is normally the root. `:LvimTex main` toggles it to the
current file and back; the choice is remembered per project. On a book this is
the one real speed lever — the engine is handed one chapter instead of the whole
document.

A target that has no PDF yet is BUILT by the toggle (`root.build_on_toggle`):
you toggled in order to see that file, and reporting a state instead would ask
for a save of a file nobody changed, purely to make the tool act. A target that
already has a PDF is SHOWN — a closed viewer is opened for it when
`viewer.open_on_start` allows one to be opened unprompted, and an already-open
one is re-pointed.

Two things follow the target, and both used to be silent bugs: the artefact
directory (see |lvim-tex-outdir|), and the ENGINE. A `% !TEX program` directive
lives in the PREAMBLE, so a subfile has none of its own — it inherits the
project's, or compiling one chapter of a book that asks for xelatex would fall
back to the default engine and die on the first font package. An open viewer is
re-pointed at the new PDF as well.

                                                               *lvim-tex-graph*
The INCLUDE GRAPH is scanned from the root with the `latex` grammar and holds
every file the document pulls in (`\input`, `\include`, `\subfile`, `\import`,
`\addbibresource`, `\bibliography`, `\includegraphics`, …).

                                                               *lvim-tex-watch*
The WATCH SET — the files a rebuild should react to — comes from latexmk's own
dependency records, not from the graph: `<jobname>.fls` for what the ENGINE
read, and `<jobname>.fdb_latexmk` for what every latexmk RULE read. Both are
needed: a `.bib` is read by biber and never by the engine, so it appears only in
the second. Generated artefacts and the TeX distribution's own files are
excluded. Before the first build there is no such record, so the include graph
stands in.

5. BUILDING                                                  *lvim-tex-building*

`:LvimTex build` compiles the current target with the active builder (latexmk by
default). Three rules govern a run:

SINGLE-FLIGHT   One build per project. A request arriving while a build is in
                flight sets ONE pending flag, so a burst of saves collapses into
                the run in progress plus one rerun afterwards. latexmk's own
                watch mode is deliberately not used: scheduling stays here, and
                there is no long-lived child process.

WATCHDOG        A run outliving `continuous.timeout` is killed.

RERUN LOOP      How many engine passes are needed, and when biber/bibtex has to
                run in between, is latexmk's job and is delegated to it.

                                                          *lvim-tex-continuous*
CONTINUOUS      `:LvimTex continuous` arms a SAVE-DRIVEN rebuild for the current
                project (per project, so one document can watch while another
                does not). Three inputs decide it, in order:
                `continuous.enabled` is the master switch; a project you have
                TOGGLED keeps your choice; a project you never toggled takes
                `continuous.auto_start`. So `auto_start = true` means "rebuild
                on save from the start", and `,la` still turns it off for one
                document.

                A save rebuilds only when the written file is one the build
                actually READS — that set comes from latexmk's own dependency
                record (see |lvim-tex-watch|), so a changed `.bib`, `.sty` or
                generated input triggers a rebuild while an unrelated file in
                the same directory does not. A burst of saves is debounced
                (`continuous.debounce`) into ONE build, and single-flight
                collapses whatever still overlaps.

                                                             *lvim-tex-builders*
BUILDERS        `latexmk` (default) owns the rerun loop. `tectonic` is one
                binary with no distribution. `latexrun` keeps intermediates in
                its object directory and copies the PDF out — lvim-tex names
                both explicitly so the log, the SyncTeX data and the PDF land
                where everything else looks, and its ONE clean action means
                `:LvimTex clean` removes the PDF as well. `arara` runs the
                workflow the DOCUMENT declares in its own `% arara:` directives
                and has no output directory at all, so `out_dir` is ignored for
                it (health says so). `custom` is any command.

                `texpresso` has a config entry and a health probe but is NOT a
                batch build: it is an engine and a viewer in one long-lived
                process that writes no PDF, produces no log and never exits.
                Selecting it is refused with that explanation instead of timing
                out two minutes later. Its live session is separate work and is
                not implemented.

                                                            *lvim-tex-selection*
SELECTION       `<localleader>lL` in visual mode (or `:'<,'>LvimTex selection`)
                compiles the selected text as a document of its own, reusing
                the ROOT's preamble — everything from `\documentclass` to
                `\begin{document}`, copied verbatim — in a scratch project under
                `stdpath("cache")`, and opens the result in the viewer. The TeX
                search paths point back at the project, so a preamble that
                inputs a local macro file or names a `.bib` still resolves, and
                an error is reported against YOUR line in YOUR file.

                What does NOT carry over: anything defined after
                `\begin{document}` (a `\newcommand` in the body, a counter, a
                `\label` elsewhere), so references outside the selection render
                as `??`. A package the preamble does not load is not guessed
                for you. The selection must be balanced — half a `figure` is
                not a document.

                                                              *lvim-tex-outdir*
`out_dir` (default `"build"`, `false` = beside the source) decides where the
artefacts go, and the two cases follow DIFFERENT rules. A configured directory is
ONE place for the whole project, so it hangs off the ROOT's directory and is
passed to the builder with its out-dir flag. `false` means "where the engine
runs", which is the TARGET's own directory — so a toggled subfile
(|lvim-tex-target-toggle|) writes its `.pdf` and `.log` beside ITSELF. It it is created if missing, because latexmk will not create
it itself. Note that a log records paths relative to the directory the ENGINE
ran in — the target's own directory — never relative to the out dir.

                                                             *lvim-tex-program*
A `% !TEX program = …` directive naming an engine (xelatex, lualatex, pdflatex,
dvipdfmx) becomes the matching latexmk flag. A directive naming one of the
`builders` keys selects that backend instead.

5a. STRUCTURE & NAVIGATION                                 *lvim-tex-navigation*

TABLE OF CONTENTS                                                *lvim-tex-toc*

`:LvimTex toc [split|float|area|bottom]` (`<localleader>lt`) toggles the table
of contents.

The document is read as ONE whole: each file is parsed with the `latex` grammar,
an `\input` splices the included file in at its own position, and the hierarchy
is rebuilt from the sectioning levels — so a `\section` written in a chapter
nests under the `\chapter` written in the root. Numbers are computed the way the
standard classes count: `\part` is Roman and independent, the dotted chain starts
below it, a starred section takes no number.

Keys inside the panel (all `outline.keys`): >
    <CR>    jump to the entry (closes the panel when `auto_close`)
    o       jump, but keep the cursor in the panel
    l / h   expand / collapse (or go to the parent)
    - / +   fold one level shallower / deeper
    1-7     fold to that sectioning depth
    zR / zM unfold / fold everything
    i r d n toggle include / label / todo rows and the section numbers
    s       filter the tree
    a       actions for the row under the cursor
    R       re-read the document
    g?      the key list
    q       close
<
FILE JUMPS                                                        *lvim-tex-gf*

`gf` (and `<C-w>f` / `<C-w>gf`) resolve the include under the cursor. The
extension list is per command (`nav.extensions`); the search path is the current
file's directory, the root's directory, then `\graphicspath`; `\usepackage` and
`\documentclass` fall through to `kpsewhich`. Not on an include, the built-in
`gf` runs unchanged. A TeX include that does not exist reports the candidates it
tried and offers to create it (`nav.create_missing`).

FINDERS                                                      *lvim-tex-finders*

`:LvimTex files` `:LvimTex labels` `:LvimTex cites` — the project's files, every
`\label` with its section, and the bibliography entries plus every cited key
with no entry.

5b. EDITING                                                   *lvim-tex-editing*

TEXT OBJECTS                                              *lvim-tex-textobjects*

Operator-pending and visual, from the treesitter queries this plugin ships: >
    ae ie   environment  (\begin{x} … \end{x})
    ac ic   command with its arguments / the argument list
    a$ i$   math zone  ($…$, \[…\], math environments)
    ad id   delimiter pair  (\left…\right, brace / bracket groups)
    am im   one \item
    aa ia   one argument group
    a%      a comment
<
The cursor only has to be inside the OBJECT, not inside the part being
selected — `ic` works with the cursor on `\frac`. Repeating an object in visual
mode expands it to the next enclosing instance, and the objects dot-repeat as
operator arguments (`dae` then `.`).

MOTIONS                                                       *lvim-tex-motions*

Normal, visual and operator-pending, count-aware (`3]m`): >
    ]]  [[   next / previous section        ][  []   its end
    ]m  [m   environment start              ]M  [M   environment end
    ]n  [n   math zone start                ]N  [N   math zone end
    ]i  [i   next / previous \item
<
MATCHING PAIRS                                                  *lvim-tex-match*

`%` jumps between `\begin` and `\end`, `\left` and `\right`, and the two ends of
a math zone or a brace / bracket group — resolved from the PARSE TREE, so an
`\end{…}` inside a verbatim block or a comment is never mistaken for the closer.
With the cursor on anything else the built-in `%` runs unchanged.
`matchparen.enabled` (off by default) additionally highlights both delimiters;
`:LvimTex matchparen` toggles that at runtime.

OPERATORS                                                   *lvim-tex-operators*
>
    cse     change the surrounding environment (both ends, ONE undo step)
    dse     delete the surrounding environment, keeping its body
    tse     toggle the starred form (environment, command, or a sectioning
            command on its heading row)
    csc     rename the surrounding command, keeping its arguments
    dsc     delete the surrounding command, keeping its first argument
    tsd tsD cycle the delimiter modifiers forward / backward
    tsf     toggle \frac{a}{b} ⇄ an inline division
<
FOLDING & INDENT                                             *lvim-tex-syntax*

Both are DELEGATED. The folds come from the latex query bundle through
|vim.treesitter.foldexpr()|, applied to TeX buffers alone by `fold.enabled`.
The indent runs the `indents.scm` this plugin ships inside lvim-ts's query
engine; `indent.keys` is the 'indentkeys' value that re-indents a `\end{…}` as
it is typed. `indent.enabled = false` means lvim-tex leaves 'indentexpr' alone —
lvim-ts applies the same query on its own when it is installed, and turning THAT
off is lvim-ts's option, not this one.

lvim-tex also registers the `tex`/`plaintex` → `latex` and `bib` → `bibtex`
parser mapping, which Neovim does not ship: without it nothing that resolves a
grammar from the FILETYPE — folding, treesitter highlighting, the query indent —
works in a TeX buffer at all.

5c. CONCEAL                                                   *lvim-tex-conceal*

`\sum_{i=1}^{n} \alpha_i \le \left( \beta \right)` reads as `∑ᵢ₌₁ⁿ αᵢ ≤ (β)`
while the file on disk stays exactly what you typed. `:LvimTex conceal`
(`<localleader>ln`) turns it on for a buffer; `conceal.enabled = true` opens
every TeX buffer concealed.

What is drawn comes from the PARSE TREE, not from patterns: a `\alpha` inside a
verbatim body, a `%` comment or an `lstlisting` is not a command to the grammar,
so it is never touched. The cost of that choice, stated plainly: while an edit
leaves a region unparseable, the concealment there is briefly stale.

GROUPS (`conceal.groups`; `conceal.math_only` says WHERE each applies) >
    math_symbols   \alpha → α, \sum → ∑, \le → ≤          maths only
    scripts        x^{2n} → x²ⁿ, a_i → aᵢ                  maths only
    delimiters     \left( → (, \left\langle → ⟨            maths only
    accents        \'{e} → é, \"o → ö, \hat{a} → â         everywhere
    styles         \textbf{x} → x (painted), \mathbb{R} → ℝ everywhere
    refs           \ref{k} → 󰓹k, \cite{k} → 󰧮k             everywhere
    sections       \section{T} → 󰉹T   (off by default)     everywhere
<
`:LvimTex conceal <group>` toggles one group everywhere, live.

A script is concealed only when EVERY character of it has a Unicode script form
— `x^{2n}` becomes `x²ⁿ`, `x^{2q}` is left alone, because Unicode has no
superscript `q` and half-lowered text reads worse than the source. Accents
follow the same rule: only combinations that exist precomposed (which is why
there is no `\vec`).

`conceal.level` and `conceal.cursor` are 'conceallevel' and 'concealcursor', set
with `:setlocal` semantics while a TeX buffer is displayed — the value in every
other buffer is untouched, and turning conceal off restores exactly what was
there. The default `cursor = "nc"` keeps the cursor line concealed in normal and
command mode and reveals it in insert and visual mode.

YOUR OWN CHARACTERS                                      *lvim-tex-conceal-maps*

`conceal.maps` is merged OVER the shipped tables, per group: an entry for a
command replaces the shipped one, every command not named keeps its glyph. >lua
    require("lvim-tex").setup({
        conceal = {
            enabled = true,
            maps = {
                math_symbols = { ["\\alpha"] = "A", ["\\myop"] = "⨁" },
                refs = { ["\\label"] = "󰓹" },
                styles = { ["\\textsc"] = "@markup.strong" },
                accents = { ["\\'"] = { y = "ý" } },
            },
        },
    })
<
A `styles` value is either a HIGHLIGHT GROUP (the wrapper is hidden and the
argument painted with it — conceal can replace a range with a character but
cannot make text bold) or a LETTER TABLE (`\mathbb` → `{ R = "ℝ", … }`).
`accents` values are always letter tables.

COST            Ephemeral extmarks in a decoration provider, over the VISIBLE
                rows only, memoised against the buffer's changedtick — so
                repainting an unchanged screen computes nothing. Measured on a
                2000-line all-maths document (48-row window, ~24 marks per row,
                min/median of 7 passes): +3.8 ms per full-page redraw, +1.2 ms
                per one-line scroll, +0.78 ms per cursor move. With conceal off
                the provider costs 0.012 ms per redraw — the same as not having
                one.

5d. COMPLETION & TOOLS                                     *lvim-tex-completion*

Completion is TEXLAB's, wired by lvim-lang: cite keys from every bibliography
the document loads (with the formatted reference on resolve), `\label`s with
what they label, commands and environments with the package they come from,
package and class names from the whole TeX tree, glossary and acronym keys, and
file paths for every include command — all of it cross-file.

lvim-tex adds ONLY what texlab does not answer, measured command by command
against a multi-file, multi-bib fixture: the `\glsentry…` family (plus
`\glsxtrshort`, `\glsxtrlong`, `\glsadd`), `\nameref` / `\cpageref` /
`\autopageref` / `\vpageref` / `\subref`, and natbib's `\Citep` / `\Citet`.

That gap-fill is ONE lvim-cmp source registered as a FALLBACK for the language
server (`completion.fallback_for`), so it runs only where the server returned
nothing at all: it cannot double up on texlab, and it stops firing on a command
the day texlab learns it. `completion.commands` is the list;
`completion.enabled = false` turns it off.

                                                          *lvim-tex-cite-menu*
CITATION ACTIONS
`:LvimTex cite [key]` (`<localleader>lz`) acts on the key under the cursor: open
its DOI or URL, open the PDF its `file` field names, jump to the entry in the
`.bib`, or yank the key. Which FIELDS each action reads is `cite.fields`, and
the URL templates are `cite.doi_url` / `cite.arxiv_url` — a DOI proxy or an
institutional resolver is one line, not a patch.

                                                              *lvim-tex-count*
WORD COUNT
`:LvimTex count` (`<localleader>lw`) runs `texcount -inc`, so it counts the
DOCUMENT (texcount follows `\input` and `\include` itself), not the file.
`:LvimTex count file` counts the current file alone and `:LvimTex count
selection` the visual selection.

                                                             *lvim-tex-texdoc*
PACKAGE DOCUMENTATION
`:LvimTex doc [package]` (`<localleader>ld`) opens a package's manual through
`texdoc`. The resolving form (`texdoc -l`) always runs first, because the
opening form detaches and its "no documentation" would otherwise be invisible.

5e. MATHS ABBREVIATIONS & SNIPPETS                              *lvim-tex-imaps*

With `imaps.enabled`, a leader (a BACKTICK, as in the tool this replaces, so the
abbreviations transfer with the rest of the keys) plus a short mnemonic expands
the moment it is typed: >
    `a → \alpha      `ve → \varepsilon    `-> → \to
    `o+ → \oplus     `R  → \mathbb{R}     `in → \in
<
and ONLY inside a maths zone. In prose, in a comment, in a verbatim body or
inside the `\text{}` of a formula the two characters typed stay text. The zone
comes from the PARSE TREE (the same answer conceal uses), so an unterminated
`$x `a` still counts as maths. The backtick is safe despite `` `word' `` being
LaTeX's opening quote: that form does not occur inside maths.

93 abbreviations ship in 8 groups. `:LvimTex imaps` (`<localleader>lm`) lists
them all — keystrokes, the LaTeX, the glyph, the group — and toggles the feature
from the window's footer; `:LvimTex imaps on|off|toggle` does the same from the
command line. `imaps.mappings` merges OVER the shipped table, `imaps.disable`
drops entries.

NO TRIGGER MAY BE A PREFIX OF ANOTHER. They auto-expand, so the shorter always
fires first and the longer could never be reached; `:checkhealth lvim-tex` names
any pair that breaks it. `j`, `J`, `K`, `M`, `O`, the digits 1-5/7/9 and `&`,
`#`, `_`, `:`, `;`, `?` are unassigned on purpose.

The MECHANISM is lvim-snippets' postfix engine: lvim-tex registers one rule per
abbreviation there rather than running a second insert-mode watcher of its own.
lvim-snippets must be installed with its `postfix.enabled` left on — health
reports both halves separately.

                                                          *lvim-tex-close-env*
CLOSING AN ENVIRONMENT WHILE TYPING

`]]` in insert mode writes the `\end` of the innermost environment that is still
open, or the `\right` of an open `\left` delimiter — read from the parse tree,
so a `\begin` inside a verbatim body is never a candidate and standing inside a
COMPLETE environment does nothing instead of writing a second `\end`. A
delimiter closes inline; an environment closes on its own line, indented like
its `\begin`, with a blank body line left under a just-typed `\begin{…}`
(`edit.close_env_body`). With nothing open the key types itself, exactly as `%`
and `gf` fall back to the built-ins.

                                                           *lvim-tex-snippets*
SNIPPETS

lvim-tex ships a `tex` collection (71 snippets: document skeletons, sectioning
with labels, environments, maths constructs, references, formatting) and
registers it with lvim-snippets as an extra collection ROOT — scanned AFTER your
own `paths`, so it can never outrank or replace them. `snippets.enabled = false`
opts out.

Rule of thumb: anything with an argument or limits (`\frac`, `\sum_{}^{}`, an
environment) is a snippet; a bare symbol is an abbreviation.

6. DIAGNOSTICS                                            *lvim-tex-diagnostics*

A TeX log is a transcript, not a diagnostic stream, so it is parsed in three
passes: records are un-wrapped and attributed to a file through the log's paren
nesting (a `(` that opened no file is still tracked, so a message's own
`(natbib)` continuation marker cannot pop a real file off that stack; and lines
are joined only when the log demonstrably wraps at the 79-column default, since
TeX never writes a line longer than `max_print_line` and our builds raise it); the four position-carrying shapes are classified (`file:line:` errors,
warning blocks with their `on input line N` tail, over/underfull boxes, and the
bare `!` error form); then the rule table refines each record.

Entries are published as |vim.diagnostic| in lvim-tex's own namespace, on the
file each entry NAMES — usually not the buffer you built from. Buffers written
to by the previous run are cleared first, so a fixed error disappears. A file
that is not open yet still receives its entries: they are there when you open
it.

`diagnostics.quickfix` decides when the quickfix list is opened: `"never"`,
`"on_error"` (the default) or `"always"`. `diagnostics.boxes` adds over/underfull
box reports, off by default because they are near-constant in real documents.
`diagnostics.ignore` holds Lua patterns; a matching message is dropped.

6a. VIEWING                                                   *lvim-tex-viewing*

The viewer is ONE interface with many implementations, and the build lifecycle
addresses it by what a viewer can DO, never by which one it is:

    reload = "auto"   it notices the file changed by itself — we do nothing
    reload = "push"   we must tell it (our own page, over its websocket)
    reload = "none"   it cannot reload; the user re-opens it (health says so)
    status            it can show OUR build state over the last render
    inverse           a click in it can reach the editor (a later phase)
    forward "quiet"   it can be moved to a position WITHOUT taking the focus
    forward "raises"  moving it always presents its window
    forward false     it cannot be moved at all

DEFAULT VIEWER  lvim-preview's PDF page — already in the ecosystem, on every
                platform, nothing to install, and the only viewer that can
                render a build state. The PDF is registered as an lvim-preview
                ARTIFACT before the first build, so the page opens immediately
                and says "building" rather than failing on a file that does not
                exist yet.

                A starting build raises "building" over the LAST GOOD render, a
                failed one an error strip naming the first error, a successful
                one refetches the file. A failed build never swaps the render:
                a PDF from a failed run is stale or half-written, and replacing
                it would lose the page you were reading.

                The artifact is deliberately NOT filesystem-watched. A build
                writes its PDF several times across its reruns, and only the
                build knows which write was the final, coherent one.

                How the PAGE behaves — position restore across a reload, lazy
                rasterisation, the highlight duration — is lvim-preview's own
                configuration and is not mirrored here: one owner.

SELECTION       `viewer.name = "auto"` takes the first available of
                `viewer.priority` (a per-OS default list, preview first).
                Naming a viewer explicitly is honoured STRICTLY — a configured
                viewer that is missing is an error, never a substitution.

                `:checkhealth lvim-tex` prints this machine's viewer matrix and
                distinguishes three states: planned but not in this version,
                implemented but not installed here, and ready.

OPENING         `viewer.open_on_start` opens the viewer as a build starts, for
                a viewer that can show the build state; one that cannot is left
                until there is a PDF worth opening. `:LvimTex view` opens it at
                any time and never builds first.

                                                    *lvim-tex-viewer-liveness*
LIVENESS        Whether a viewer is still on screen decides whether the
                cursor-follow may move it, and for a SINGLE-INSTANCE viewer it
                cannot be answered by the process we spawned: a second
                invocation hands its file to the running window and exits
                within a fraction of a second, leaving nothing to track. okular
                is therefore asked over the session bus — `org.kde.okular`,
                `/okular`, `currentDocument()` — behind a short cache, so the
                question stays free to ask on every cursor pause. It compares
                the DOCUMENT, not merely "okular is running": when you have
                tabbed away to something else, a follow you never asked for
                must not drag the tab back.

                                                     *lvim-tex-viewer-focus*
FOCUS           An automatic forward search must never take the keyboard. Some
                viewers can be told (okular `--noraise`, sioyek `--nofocus`,
                Skim `displayline -g`) and some cannot — evince's `SyncView`
                and Sumatra's `-forward-search` present their window every
                time. Each viewer declares which it is, `synctex.follow_cursor`
                drives only the quiet ones, and the explicit `:LvimTex view`
                drives all of them (there the raise is the point).

                A viewer SPEC may override that declaration with
                `forward = "quiet" | "raises" | false`, for the case the plugin
                cannot detect: a viewer whose quietness is its own SETTING.
                zathura is that case — it presents its window on every D-Bus
                command (`--synctex-forward` becomes `SynctexView`) unless its
                `dbus-raise-window` option is off, so it does not follow the
                cursor by default. `viewer.zathura.forward = "quiet"` turns
                that option off in the instance lvim-tex launched, over
                zathura's own `ExecuteCommand` — the one D-Bus call exempt from
                the raise — leaving your zathurarc untouched. The trade is
                all-or-nothing: no sync raises zathura afterwards, `:LvimTex
                view` included.

6b. SYNCTEX                                                   *lvim-tex-synctex*

`-synctex=1` makes the engine record where each piece of the PDF came from;
the `synctex` utility is the only thing that reads that record, and lvim-tex is
the only thing here that speaks to it:

    forward   `synctex view -i <line>:<col>:<file> -o <pdf>` → Page / x / y
    inverse   `synctex edit -o <page>:<x>:<y>:<pdf>` → Input / Line / Column

A viewer with SyncTeX support of its OWN is handed the source position instead
and resolves it itself — asking on its behalf would be a second resolution that
can only disagree with the viewer's.

FORWARD         `:LvimTex view` (`<localleader>lv`) opens the viewer and puts
                it at the paragraph under the cursor. `synctex` answers at
                paragraph granularity: that is what the format records, not a
                rounding error here — ONE source line has one anchor, so a long
                paragraph that wraps over four typeset lines is marked at the
                line TeX recorded, not at each of them.

                A BLANK line (or one holding only a comment) is typeset as
                nothing, so `synctex` has no record for it and would answer with
                the nearest node it does know — measured on a real book, a blank
                line between two paragraphs resolved to the chapter heading on
                the PREVIOUS page. Such a line is resolved to the nearest line
                that puts something on the page, downwards first.

                The band covers the typeset BOX (`h`/`v`/`W`/`H`), not the point
                `x`/`y`: `v` is on the BASELINE, so a band anchored at `y` and
                grown downwards sits a whole line below the text and runs to the
                page edge. `synctex.forward_on_build` does the same
                after every successful build, so the viewer follows what you
                are editing with no keystroke.

                A SCROLL counts as movement too (`synctex.follow_scroll`):
                a wheel, CTRL-E/CTRL-Y or `zz` moves the view while the cursor
                stays put, so a viewer answering only the cursor sits still
                through the whole of it. A scroll is answered with the WINDOW
                CENTRE — the cursor is no longer where you are looking.

                `synctex.follow_cursor` does it continuously: after the cursor
                has been still for `follow_debounce` ms the page moves to the
                paragraph it sits in. It never OPENS a viewer — it only moves
                one that is already open — and it is silent when the PDF has no
                SyncTeX data for that file, so a buffer that was not part of the
                last build costs nothing. Debounced rather than per-move because
                each follow is a `synctex` process.

                                                      *lvim-tex-inverse-search*
                                                    *lvim-tex-follow-back*
FOLLOW BACK     The same link the other way: scrolling the PDF page moves the
                SOURCE to the text you are looking at. Only the default page
                can do it — it is the only viewer that reports where its reader
                is. The page sends the point at the top of its viewport,
                `synctex edit` turns that into a file and a line, and the
                window already showing that file scrolls to it.

                Needs lvim-preview's `artifact.allow_client_messages`, the same
                gate as ctrl-click; `synctex.follow_back.enabled` then decides
                whether the frames are acted on.

                HOW PRECISE. SyncTeX records one anchor per source LINE,
                which in prose is usually a whole paragraph — so this
                direction resolves to the paragraph being read, not the
                sentence. That is the data's granularity, not a defect. A
                report whose resolved line turns out to be on another page, or
                further than `follow_back.tolerance` PDF points from the point
                that produced it, is DROPPED rather than acted on (a page's
                margins carry no text, so a lookup there would otherwise
                resolve to an arbitrary paragraph).

                                                       *lvim-tex-reverse*
ASKING          `:LvimTex reverse` (`<localleader>lr`) is the reverse of `,lv`:
                it asks the viewer which page it is showing and JUMPS the
                cursor there — a command, so it moves the cursor and says so
                when it cannot, unlike the silent follow below. It ignores
                `follow_back.poll.enabled`: that switch decides whether the
                editor follows by ITSELF; asking is always allowed.

                BY THE PAGE, for an external viewer. Only the default page
                reports a POSITION. zathura publishes `pagenumber` and okular
                answers `currentPage()`, and NEITHER emits any signal when it
                changes — zathura's whole D-Bus interface carries one signal,
                for ctrl-click. So `follow_back.poll` asks on a timer (a read
                costs ~3 ms) and the source moves a page's worth when you flip
                a page, nothing in between. Off by default.

                The query point (`poll.x` / `poll.y`) sits INSIDE the text
                block on purpose: a page's margins carry no text, so a lookup
                there resolves to whatever record is nearest.

                Three rules make a two-way link usable instead of a fight:
                  * MOVE THE VIEW, NOT THE CURSOR (`follow_back.move`).
                    Scrolling is reading, not editing.
                  * NEVER FOCUS OR OPEN a window. A file you are not looking at
                    is not moved at all.
                  * OWNERSHIP. Whoever moved the other side last owns the link
                    for `follow_back.settle` ms, so the echo of our own forward
                    search is dropped rather than answered. The loop is broken
                    by construction, not damped.

INVERSE         A click in the viewer moving the cursor here. It needs the
                viewer to be able to REACH this Neovim, and it already can:
                `v:servername` names the socket, so the launch command embeds
                `nvim --server <socket> --remote-expr "…"`. Nothing extra is
                installed (no neovim-remote) and no shim script is written.

                `synctex.inverse = false` refuses every such request.

                Per viewer:
                  preview   ctrl-click, once lvim-preview's own
                            `artifact.allow_client_messages` is enabled — its
                            setting, in its config; `:checkhealth lvim-tex`
                            prints the line to add.
                  zathura   automatic when lvim-tex launched it (`-x`).
                  okular    automatic when lvim-tex launched it
                            (`--editor-cmd`).
                  sioyek    automatic when lvim-tex launched it
                            (`--inverse-search`).
                  Skim      a ONE-TIME setting in Skim's Preferences → Sync;
                            health prints the exact Command and Arguments.
                  Sumatra   automatic when lvim-tex launched it
                            (`-inverse-search`).
                  evince    not claimed: the reverse direction is a `SyncSource`
                            SIGNAL, which means holding a monitor process for
                            the viewer's lifetime. Forward search over D-Bus IS
                            verified against the local binary.

HONESTY         Health never reports an unproven module as ready. It separates
                what was verified against a real binary on this machine
                (preview, zathura, okular, evince) from what follows the
                viewer's own documentation, on a machine or platform that could
                not run it (sioyek, Skim, SumatraPDF).

7. ADDING A LOG RULE                                        *lvim-tex-log-rules*

Per-package meaning is DATA. Coverage grows by adding a row, never by editing
the parser. A rule: >lua
    {
        id = "mypkg.deprecated",     -- reported by :LvimTex info
        pkg = "mypkg",               -- for documentation and health
        match = "is deprecated, use", -- a Lua pattern, or fun(rec): boolean
        severity = vim.diagnostic.severity.WARN,
        extract = function(rec)      -- refine file/lnum/col/message
            local old = rec.text:match("`(.-)'")
            return { message = ("mypkg: %s is deprecated"):format(old or "?") }
        end,
    }
<
The record passed to `match`/`extract` carries `text` (the un-wrapped message),
`file`, `lnum`, `kind` (`error`|`warning`|`box`|`info`) and `raw`.

Returning `false` from `extract` DROPS the record. Rules from
`diagnostics.rules` are tried after the shipped set, so matching the same text
overrides a shipped verdict. A record matching no rule is still reported,
attributed to its file — nothing is dropped silently, which is what makes the
shipped set safe to grow one package at a time.

Rules ship for: the LaTeX kernel, hyperref, biblatex/biber/bibtex,
babel/polyglossia, the font machinery (NFSS, fontspec, fontenc), the layout
packages (pgf/pgfplots, geometry, microtype, amsmath, caption, float), graphics
(graphicx, the driver `.def`s, xcolor), tables and lists (array, longtable,
tabularx, multicol, enumitem), code listings (listings, minted),
cross-referencing (cleveref, varioref, natbib) and the engine itself (inputenc,
the TeX capacity limits). `:checkhealth lvim-tex` prints the current count per
package.

Group ORDER inside the shipped set is load-bearing where two packages describe
the same failure: the graphics rules precede the kernel's generic missing-file
rule, and the cross-referencing rules precede biblatex's, so natbib's empty
bibliography is not reported as an empty bibtex entry.

9. KEYMAPS                                                    *lvim-tex-keymaps*

Every map is BUFFER-LOCAL to `config.filetypes` and hangs off `<localleader>`,
so the group exists only inside a TeX buffer and the global `<leader>` groups
are untouched. The effective key is `keys.prefix .. <suffix>`; with the default
prefix and `maplocalleader = ","`, `keys.build` reads `,ll`.

    <localleader>ll     build
    <localleader>la     toggle the save-driven rebuild loop
    <localleader>lo     open the build panel
    <localleader>lm     list the maths abbreviations
    <localleader>lz     citation actions for the key under the cursor
    <localleader>lw     word count
    <localleader>ld     documentation for the package under the cursor
    <localleader>ln     toggle conceal
    <localleader>lt     toggle the table of contents
    <localleader>lf     find a file in the project
    <localleader>lg     find a \label in the project
    <localleader>lb     find a citation in the project
    gf                  jump into the include under the cursor
    <localleader>lv     open the PDF viewer and jump it to the cursor
    <localleader>lL     (visual) compile the selection as a document
    <localleader>lk     stop this build
    <localleader>lK     stop every build
    <localleader>lc     clean auxiliary files
    <localleader>lC     clean everything
    <localleader>le     open the quickfix list
    <localleader>ls     toggle the compile target
    <localleader>li     project info
    <localleader>lx     reload the project data

Set a suffix to `false` to leave it unmapped; change `keys.prefix` to move the
whole group. Every map carries a `desc`, so lvim-keys-helper shows them with no
central registration.

11. CONFIGURATION                                       *lvim-tex-configuration*

Every glyph, timeout, binary, argv, key and layout is an option. See the README
for the complete default table; the entries that shape behaviour most:

builder         Active backend, a key of `builders`. Default `"latexmk"`.
builders        Per-backend `{ bin, args, out_dir_flag }`. `out_dir_flag` is a
                format string (`"-outdir=%s"`).
out_dir         Build directory, relative to the root's own directory. `false`
                keeps every artefact beside the source — `false` and not `nil`,
                because a nil value in a Lua table is an ABSENT key, so
                `setup({ out_dir = nil })` would merge nothing at all.
root            `magic_comment`, `scan_lines`, `markers`, `subfiles`,
                `build_on_toggle`.
continuous      `enabled`, `auto_start`, `on_save`, `timeout`, `debounce`.
diagnostics     `enabled`, `warnings`, `boxes`, `quickfix`, `ignore`, `rules`.
panel           Build-panel layout: `"float"`, `"area"` or `"bottom"`.
viewer          `enabled`, `name`, `priority`, `open_on_start`, plus a
                `{ bin, args }` table per external viewer
                (see |lvim-tex-viewing|).
synctex         `bin`, `inverse`, `forward_on_build`, `follow_cursor`,
                `follow_debounce` (|lvim-tex-synctex|).
selection       `dir`, `suffix`, `view`, `timeout` (|lvim-tex-selection|).
outline         `layout`, `position`, `width`, `follow`, `auto_close`,
                `fold_level`, `max_level`, `todo_keywords`, `show`, `keys`
                (|lvim-tex-toc|).
nav             `extensions`, `kpsewhich`, `create_missing` (|lvim-tex-gf|).
textobjects     `enabled` (|lvim-tex-textobjects|).
motion          `enabled` (|lvim-tex-motions|).
fold            `enabled`, `level` (|lvim-tex-syntax|).
indent          `enabled`, `keys` (|lvim-tex-syntax|).
matchparen      `enabled`, `highlight`, `priority` (|lvim-tex-match|).
conceal         `enabled`, `level`, `cursor`, `groups`, `math_only`, `maps`
                (|lvim-tex-conceal|).
imaps           `enabled`, `leader`, `mappings`, `disable` (|lvim-tex-imaps|).
snippets        `enabled` (|lvim-tex-snippets|).
cite            `doi_url`, `arxiv_url`, `fields`, `yank_register`
                (|lvim-tex-cite-menu|).
count           `bin`, `args`, `per_file`, `timeout` (|lvim-tex-count|).
docs            `bin`, `args`, `list_args`, `timeout` (|lvim-tex-texdoc|).
completion      `enabled`, `priority`, `fallback_for`, `trigger_chars`,
                `commands`, `glossary_definitions`, `glossary_loaders`
                (|lvim-tex-completion|).
filetypes       Filetypes lvim-tex attaches to.
notify          Emit |vim.notify| lines for lifecycle events.
output_lines    Trailing raw-output lines kept per project.
keys            `prefix` plus one suffix per action (see |lvim-tex-keymaps|).
icons           Nerd Font glyphs; all defaults are single-width.

Options for features that have not landed yet (`outline`, `imaps`, the editing
operators, and the per-viewer tables of the viewers still to come) are already
present so the shape does not change under you later; they take effect as each
phase ships.

12. HEALTH                                                     *lvim-tex-health*

`:checkhealth lvim-tex` reports the active builder and its binary, the `latex`
and `bibtex` grammars (with the install line when one is missing), the LSP side
owned by lvim-lang, the log-rule count per package, any internally inconsistent
config value, this machine's VIEWER MATRIX (|lvim-tex-viewing|), and — for the
